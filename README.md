# 英検2級 面接ノート

中学生が一人で、英検2級二次試験の流れと回答を練習するための非公式Webアプリです。既存の音声テストアプリの録音・再生・端末内英語読み上げを土台にしています。公式教材の文章・画像は転載せず、5セットの問題と15コマのSVGイラストを独自作成しました。

HTML / CSS / JavaScriptのみ。ログイン、APIキー、外部AI、広告、分析タグ、データベース、サーバー側処理は不要です。GitHub Pagesで配布できます。**この作業ではGitHubへのアップロード・push・公開更新は行っていません。**

## できること

- 模擬面接：入室、面接カードを渡す、着席、名前・級の確認と挨拶、問題カード受領、黙読20秒、音読、No.1、準備20秒、No.2、カードを裏返す、No.3・4、カード返却・退室、振り返り。
- 問題別練習：No.1のみ、No.2のみ、No.3・4。
- オリジナル5セット：本の交換、食品ロス、地域の庭づくり、修理と再利用、デジタル支援。本文は60・62・61・63・62語（タイトルを除く）です。
- 英文の手入力、iPhoneの標準キーボードによる英語音声入力、録音・再生、面接官の質問の英語読み上げ。
- 回答文、確認項目、自己評価、苦手印、途中の練習、過去の履歴の端末内保存。
- JSONファイルによる履歴のエクスポートとインポート。

英語の内容・発音を自動採点しません。自己評価から公式点数、合否、合格率を推定する機能もありません。模範解答は唯一の正解ではありません。

## 公式形式との対応

[日本英語検定協会・2級の試験内容](https://www.eiken.or.jp/eiken/exam/grade_2/solutions.html) の二次試験案内を2026年11月15日に確認しました。

| 公式の流れ | このアプリ |
| --- | --- |
| 英語による個人面接、約7分 | 英語の面接官プロンプトと日本語の補助説明。全体の強制終了はせず、自分のペースで進む |
| 約60語の英文を20秒黙読し、タイトルから音読 | 全5セットに本文と20秒タイマー、音読ステップ |
| No.1：英文内容 | 本文の方法・理由・目的を問う質問 |
| No.2：3コマの展開説明、考慮時間20秒、書き出し文 | オリジナルSVG3コマ、準備タイマー、書き出し文 |
| No.2の後にカードを裏返す | No.3・4ではカードを非表示 |
| No.3：カードに関連する意見 | 社会的なテーマに賛否・理由を述べる |
| No.4：日常生活の一般的な意見 | Yes / Noを選び、Why / Why notの後に理由を話す |
| カード返却・退室 | 終了の英語のやり取り |

面接官の文言と挨拶例は独自の練習用表現です。日本語の説明、画面に表示する質問、回答入力、録音、次へボタンは学習用の補助で、本番の試験環境そのものではありません。本番ではメモ・録音・撮影は禁止されています。問題の難易度は2級を目標に作成しており、協会による認定・監修を受けた教材ではありません。

## ファイルの役割

```text
index.html       画面の構造、日本語の説明
style.css        配色、文字サイズ、スマートフォンの縦画面対応
data.js          5セットの本文、質問、模範解答、解説、確認項目
illustrations.js オリジナルSVGの人物・小物・15コマの描画
core.js          履歴のデータ形式、インポート検査、画面の順序
app.js           練習の進行、タイマー、復習、端末内保存、入出力
audio.js         既存テストアプリを基にした音声処理
.nojekyll        GitHub Pagesでそのままファイルを配信する指定
.gitignore       公開用ソースと開発用ファイルだけをGitの対象にする設定
README.md        この説明書
server.cjs       Windowsで確認するための小さなローカルサーバー
test.cjs         問題データ、入出力形式などのテスト
flow-test.cjs    ブラウザAPIを模擬した画面遷移・保存・音声結合テスト
```

アプリ本体は先頭7ファイルです。外部ライブラリのインストールやビルドは不要です。`server.cjs` は開発時だけ使用し、GitHub Pages上では実行しません。

## Windowsで起動する

この開発環境にはNode.jsが入っています。

1. PowerShellを開き、次を実行します。

```powershell
Set-Location (Join-Path ([Environment]::GetFolderPath('Desktop')) 'eiken2-interview')
node server.cjs
```

2. Chromeで [http://127.0.0.1:8000/eiken-test/](http://127.0.0.1:8000/eiken-test/) を開きます。このパスでGitHub Pagesのサブフォルダー配信も確認できます。
3. PowerShellを開いたまま練習します。終了時は `Ctrl+C` を押します。

これはPC内だけのサーバーで、外部公開はしません。`EADDRINUSE` が出たら、以前起動した同じサーバーを終了してください。Node.jsが入っていない別PCではNode.jsが必要です。`index.html` の直接オープンでも画面を確認できますが、保存・マイクの正式な確認にはlocalhostかHTTPSを使ってください。

## 実際の使い方

1. ホームで問題セットとモードを選び、「練習をはじめる」を押します。
2. 画面の説明を確認して、必要なら「面接官の英語を聞く」を押します。勝手に音声が流れることはありません。
3. 黙読・準備では「20秒を開始」を押します。終了後に「次へ」を押します。画面を離れた場合はタイマーをやり直します。再読み込みで再開する場合も20秒を再計測します。
4. 英文を回答欄に入力するか、「録音で回答」に切り替えて声で答えます。録音は1回最長2分です。停止後に再生できます。
5. No.4ではYes / Noを選んでから理由を述べます。読み上げボタンは選択後にWhy / Why notを読みます。
6. 終了後、自分の回答と模範解答を比べ、確認項目、自己評価、苦手印を付けます。これらは操作ごとに保存します。
7. 「振り返りを保存してホームへ」で完了にします。「復習・履歴」で過去の回答や苦手問題を確認できます。「この問題をもう一度」は新しい履歴で再練習します。音読の再練習は音読から面接を進めます。
8. 途中でやめる場合は「中断してホームへ」。ホームの再開ボタンは最新の未完了練習、履歴の「続きから」は選んだ練習を再開します。

自分の回答文は練習画面で編集できます。完了した履歴の回答文は振り返り画面では閲覧のみで、自己評価・苦手印・確認項目は更新できます。挨拶の名前は架空の名前で練習し、本名は入力しなくて構いません。

## iPhoneとChromebookの音声

### iPhone Safari

1. HTTPSで公開されたURLをSafariで直接開きます。
2. 「設定」→「一般」→「キーボード」で英語キーボードと音声入力を有効にします。OSによって項目名が異なる場合があります。
3. 「文字・音声入力」の回答欄をタップし、キーボードを英語に切り替えてキーボードのマイクを押します。
4. 入力された英文を修正します。録音モードに移る前に、OSの音声入力を終了してください。
5. 「録音で回答」→「録音開始」でマイクを許可し、回答後に停止・再生します。

### Chromebook Chrome

同じHTTPSのURLで、手入力、録音・再生、端末内英語音声の読み上げを使えます。ChromeOSの音声入力を利用する場合はOS側で別途英語に設定してください。学校管理の端末では、マイクや保存が制限されることがあります。

### 共通の制限・代替手段

- 録音にはHTTPS（PCではlocalhostも可）とマイク許可が必要です。未対応の場合も文字入力や声に出すだけの練習ができます。
- MediaRecorderの対応状況から録音形式を選びます。録音中は移動、文字入力、読み上げを無効にしてマイク競合を抑えます。
- 録音中は画面を開いたままにしてください。別画面への移動時は停止を試みますが、OSによる強制終了、着信、画面ロックで録音が失われる場合があります。
- 読み上げは `localService === true` の英語音声のみ。端末内の音声がない場合はボタンを無効にし、テキストで案内します。
- キーボードの音声入力はOSの機能です。アプリから英語への切り替えや音声入力の終了を強制できません。OS側の音声処理が完全に端末内かどうかも保証できません。
- SpeechRecognition APIは使用していません。録音からの文字起こしもありません。
- 今回はPWAのインストール／オフラインキャッシュ機能を実装していません。SafariやChromeのブックマークから利用してください。初回・再読み込みにはページを取得する通信が必要です。

## 保存とバックアップ

### 保存するもの

`localStorage` に、問題セットID、モード、進行位置、日時、回答文、自己評価、確認項目、苦手印、Yes / Noの選択を保存します。回答文は1欄5000文字、履歴は500件が上限です。保存上限に達したらバックアップ後に不要な履歴を削除してください。保存できなかった場合は画面上部に案内を出します。

**音声は練習中のメモリー内だけです。** 振り返りでも再生できますが、再読み込み・ページ終了で失われます。音声は履歴にもエクスポートにも含みません。残したい内容は回答欄に文字でも入力してください。

ブラウザデータ削除、プライベートモード、容量不足、端末変更などで保存内容が消えます。iPhoneとChromebookは自動同期しません。HTTPS/HTTPの違いや公開URLのパス変更でも保存場所が変わります。同じアプリは1つのタブで使ってください（複数タブで同時編集すると最後の保存が優先されます）。

### エクスポート

「復習・履歴」→「データをエクスポート」を押します。JSONファイルがダウンロードされます。iPhoneではSafariのダウンロードや「ファイル」アプリで保存先を確認してください。ファイルには回答が含まれるので、GitHubへアップロードしないでください。

### インポート

「バックアップをインポート」で、このアプリが出力したJSONを選択します。既存履歴を一括置換せず追加し、同じIDは端末側の履歴を優先します。別端末で更新した同じ履歴を上書き同期する機能ではありません。

形式・版番号、セットID、文字数、評価値、チェック項目、重複IDなどを検査し、壊れたファイルは取り込まずに案内します。読み込んだ文字はHTMLとして実行せずテキストで表示します。上限50MB／500履歴です。端末内の既存保存が壊れている場合は上書きを避けて一時利用になり、エクスポートで救出できます。取り込み後も画面上部の保存結果を確認してください。

## GitHub Pagesへの公開更新（許可後のみ）

既存の音声テスト版に対し、アップロード対象が増えています。古い3ファイルだけでは今回のアプリは動きません。

### 必須の公開ファイル

次の9ファイルを、リポジトリの同じ階層（直下）へ置きます。

- `index.html`、`style.css`、`app.js`
- `audio.js`、`data.js`、`illustrations.js`、`core.js`
- `.nojekyll`、`.gitignore`

READMEも公開して構いません。開発用の `server.cjs`、`test.cjs`、`flow-test.cjs` はGitで管理できるようにしていますが、アプリ配信には不要です。録音・エクスポートJSON・個人情報入りの記録・APIキー・`.env`・秘密鍵・ログ・スクリーンショットはアップロードしないでください。`.gitignore` はWeb画面で手動アップロードするファイルを保護しません。

### 初めて公開する場合

1. GitHubにサインインし、「+ → New repository」。リポジトリ名を `eiken-voice-check` などにします。
2. 無料の公開リポジトリを使う場合はPublicを選び、READMEなどの自動作成は選ばずCreate repository。ソースもサイトも誰でも閲覧できます。家族限定ではありません。
3. 空の画面の「uploading an existing file」、または「Add file → Upload files」から上の9ファイルを選び、`main` にコミットします。コミットは変更の保存です。フォルダーごとやZIPではなく、直下にファイルを置きます。
4. リポジトリの「Settings → Pages」でSourceを「Deploy from a branch」、Branchを `main`、フォルダーを `/ (root)` にしてSave。ここで公開が始まります。Custom domainは空欄で構いません。
5. 公開処理の完了後、Pages欄の「Visit site」または公開URLを確認します。Actionsで処理の成功・失敗を確認できます。
6. Enforce HTTPSが有効か確認します。URLは通常 `https://ユーザー名.github.io/eiken-voice-check/` です。実際にはPages欄からコピーしてください。
7. iPhone SafariとChromebook Chromeで公開URLを開き、下の実機チェックを行います。PCのローカルサーバーは不要です。

### すでにPagesで公開している場合

同じリポジトリの `main` へ、上の9ファイルを追加・更新してコミットします。**既存のPages公開設定が有効なら、ファイル更新だけで公開サイトも自動更新されます。** 公開許可後に行ってください。CSSとJavaScriptは相対パスなので、リポジトリ名をURLの一部として配信できます。

404の場合は公開処理、直下の小文字の `index.html`、`main / (root)` とURLを確認します。画面が途中で止まる場合は追加の4つのJSファイルもアップロードしたか確認してください。

## 今後の問題追加

1. `data.js` の配列内の1セットを複製します。
2. `id` を重複しない半角英数字の固定IDに変更します。既存IDを変えると過去の履歴の対応が崩れるため変更しないでください。
3. `title`（英語タイトル）、`topic`（日本語名）、`passage`（約60語）、`opening`（No.2書き出し）を設定します。
4. `scenes` に3コマの時間表示 `time`、吹き出し `bubble`、日本語の画像説明 `alt` を設定します。
5. `q1`〜`q4` の質問 `prompt`（No.2は共通指示）、模範解答 `model`、日本語解説 `explanation`、表現配列 `expressions`、確認項目配列 `checks` を入力します。No.4は `yes: "Why?"` と `no: "Why not?"`、任意の `alternative` も設定します。
6. `illustrations.js` の `content(id, i)` に新ID用の描画を追加します。データの文章だけを増やしても図は自動生成されません。各場面の行動・時刻・セリフが模範解答と一致しているか確認します。
7. `test.cjs` のセット総数の確認を新しい数に変更し、`flow-test.cjs` のテスト対象IDにも追加します。下のコマンドで検査し、画面と実機も確認します。
8. 問題の本文や内容を大きく変更する場合は既存IDを再利用せず、新しいセットとして追加してください。保存履歴は問題本文を丸ごと保存せずIDで参照します。

```powershell
node test.cjs
node flow-test.cjs
node --check app.js
node --check audio.js
```

## 品質確認

### 自動検査

- 問題文の語数、5つのIDの一意性、3コマ構成、模範解答・解説・確認項目の存在。
- No.2模範解答が指定の書き出しから始まること。
- データの保存形式・JSON往復・重複取り込み・異常値拒否。
- DOM IDの参照と相対パスのファイル存在。
- 5セット×4モードの20経路、20秒タイマー、No.3以降のカード非表示、回答入力、完了保存。
- アプリを新しく起動した場合の履歴読み込み・途中再開、画面離脱時のタイマー再準備。
- 録音との結合（模擬API）、録音中の移動制限、停止後の復帰、保存できない環境の案内。

2026年11月17日の最終検査で上記のロジックテストは合格しました。Windowsの画面操作ツールが現在のブラウザURLを安全に判定できず停止したため、実ブラウザでの画面表示・スマートフォン幅の表示確認は未完了です。CSSでは650px以下で3コマを縦並びにし、大きなボタンと16px以上の入力文字を指定していますが、実機での表示保証ではありません。これらは模擬DOM・音声APIによるロジック検査を含み、Safariの実マイクや音声入力の保証ではありません。今回の改修後も下の実機確認が必要です。
